# 物販・ビジネス向けゴールコマンド設計 — 探索と体系化

このドキュメントは「物販やビジネスに使える適切な粒度のゴールコマンドを作るためのスキルを
探索・整理した結果」をまとめたもの。設計の根拠と、利用可能なスキルの棚卸しを記録する。

## 1. 探索：`/goal` の仕組みの理解

`/goal <条件>` は **セッションスコープの Stop hook** を立て、`<条件>` が満たされるまで
セッションの停止をブロックする。条件が満たされると自動でクリアされる。

ここから導かれる設計上の制約：

- **完了条件が検証可能でないゴールは永久にブロックされる** → 検証可能性が最優先。
- **大きすぎるゴールは1セッションで終わらず張り付く** → 粒度がほぼ成否を決める。

この2点を物販文脈に落とすのが本設計の核心。

## 2. 探索：利用可能なスキルの棚卸し（物販ゴール観点）

このリポジトリ環境で使えるスキルを、物販ゴールへの寄与で分類した。

| スキル | 物販ゴールでの役割 | 関係 |
|--------|-------------------|------|
| `/goal`（組込） | 目標設定と完了監視の土台 | ★中核 |
| **`biz-goal`（本設計で新規作成）** | 願望→検証可能ゴールへの変換 | ★中核 |
| `loop` | 在庫/売上などの定例ゴールを自動反復 | ◎強く連携 |
| `deep-research` | 競合価格・市場・トレンド調査ゴールの実行手段 | ○調査系で連携 |
| `verify` | 「施策が効いたか」の検証ゴールに転用可 | ○検証系 |
| `code-review` / `simplify` / `review` / `security-review` | 主に開発向け。MCPサーバー保守時のみ | △間接 |
| `init` / `session-start-hook` / `update-config` / `keybindings-help` | 環境整備。ゴール設計には非直結 | △間接 |
| `claude-api` / `claude-code-guide` | AI実装の参照。物販ゴールには非直結 | △間接 |

**結論**：物販ゴールに直接効くのは `goal`＋新設 `biz-goal` を中核に、`loop`（定例化）・
`deep-research`（調査）・`verify`（効果検証）を脇に置く構成。これを「体系」とした。

## 3. 体系：粒度ラダー

ゴールコマンドの良し悪しの大半は粒度で決まるため、4段の共通ものさしを定義した。

```
Lv1 ミッション   月〜四半期   例「EC月商100万」        → ゴール化✗（永久未完）
Lv2 マイルストーン 1〜2週間    例「新ライン立上げ」      → 要分解
Lv3 ゴール ★      数時間〜1日  例「新商品10点の説明文作成」→ ゴール化✓ 最適
Lv4 アクション    数分        例「1商品の説明1本」      → ゴール化✗（細かすぎ）
```

ゴールコマンドは常に **Lv3** に正規化する。Lv1/2 は「今週着手する最初のLv3」へ落とす。

## 4. 体系：3条件チェック

すべてのゴールコマンドは出力前に3条件で検証する。

1. Verifiable — 完了を客観判定できる成果物と送り先があるか
2. Session-sized — Lv3 か（今日中に終わるか）
3. Actionable — 動詞始まりで入力（期間・対象・件数・送り先）が埋まっているか

## 5. 成果物（このスキルセットの構成）

```
.claude/
  skills/biz-goal/
    SKILL.md      # 中核スキル：原則・粒度ラダー・変換ワークフロー・標準フォーマット
    reference.md  # 業務5カテゴリ別テンプレ集＋/loop定例化＋完了条件の語彙
  commands/
    biz-goal.md   # /biz-goal <願望> で変換を起動するスラッシュコマンド
docs/
  goal-command-design.md  # 本書：探索結果と設計根拠
```

## 6. 使い方（クイックスタート）

1. 願望をそのままコマンドに渡す：`/biz-goal 在庫を減らしたい`
2. 返ってきた Lv3 ゴール文字列を `/goal` に貼る。
3. 定例なら `/loop 1d <ゴール文字列>` で自動反復。
4. 完了報告は LINE MCP の `send_line_message` で送る（完了条件に「LINEに送信するまで」を含めると判定が堅い）。

## 7. 物販でそのまま使える起点ゴール例

- `在庫データを読み込み、在庫10個以下の商品一覧と推奨補充数を作成し、LINEグループに送信するまで完了する`
- `今週の注文を集計し、総売上・件数・客単価・トップ5商品のサマリをLINE個人に送信するまで完了する`
- `新商品5点の商品名・150字説明・価格案・LINE告知文をMarkdown表にまとめるまで完了する`
- `直近30日の★1〜2レビューを分類し、改善アクション3案を一覧化するまで完了する`
