# reference — 物販ゴールコマンド・テンプレート集

`SKILL.md` の補助資料。業務カテゴリ別に、そのまま `/goal` に渡せる Lv3 ゴール文を並べる。
`<>` の箇所をユーザーの値で埋めて使う。全テンプレは「動詞始まり＋検証可能な完了条件＋送り先」を満たす。

---

## 1. 在庫 (Inventory)

| 用途 | ゴールコマンド（埋めて使う） |
|------|------------------------------|
| 補充アラート | `<在庫データ/CSV> を読み込み、在庫数 <閾値:10> 以下の商品一覧と推奨補充数を作成し、LINE<グループ>に送信するまで完了する` |
| 死蔵在庫の洗い出し | `直近<90>日で1件も売れていない商品を抽出し、値下げ/廃番の判断材料（在庫額・経過日数）付き一覧をMarkdownにまとめるまで完了する` |
| 棚卸し差異 | `理論在庫と実棚卸データを突合し、差異のある商品とその数量・想定原因をリスト化するまで完了する` |

## 2. 売上 (Sales)

| 用途 | ゴールコマンド |
|------|----------------|
| 週次サマリ | `今週(<6/16-6/22>)の注文を集計し、総売上・注文件数・客単価・トップ5商品を含むサマリを作成し、LINE<個人>に送信するまで完了する` |
| 前週比/異常検知 | `今週と前週の売上を比較し、±<20>%以上変動した商品と要因仮説を一覧化し、LINE通知するまで完了する` |
| 月次レポート | `<6>月の売上を集計し、日次推移・カテゴリ別構成比・前月比をまとめたレポートをMarkdownで作成するまで完了する` |

## 3. 出品・商品登録 (Listing)

| 用途 | ゴールコマンド |
|------|----------------|
| 新商品の説明文 | `新商品<5>点について、商品名・<150>字の説明文・価格案・キャッチコピーをMarkdown表にまとめるまで完了する` |
| 既存ページ改善 | `売れ行きの悪い商品<3>点の現行説明文をレビューし、改善版の説明文とタイトル案を作成するまで完了する` |
| 多販路展開 | `商品<A>を <Amazon/楽天/自社EC> 向けに、各媒体の文字数制限に合わせた説明文へ書き分けるまで完了する` |

## 4. 顧客対応 (Customer Support)

| 用途 | ゴールコマンド |
|------|----------------|
| レビュー分類 | `直近<30>日の★1〜2レビュー全件を「品質/配送/期待差/その他」に分類し、件数と代表例、改善アクション<3>案を一覧化するまで完了する` |
| 返信テンプレ整備 | `よくある問い合わせ<10>種について、丁寧語の返信テンプレートを作成しMarkdownにまとめるまで完了する` |
| 問い合わせ要約 | `未対応の問い合わせ<n>件を緊急度（高/中/低）で分類し、対応優先順リストをLINE<グループ>に送信するまで完了する` |

## 5. 販促 (Promotion)

| 用途 | ゴールコマンド |
|------|----------------|
| LINE配信文 | `<セール/新商品> の告知について、LINE配信用の本文（<200>字以内）と配信タイミング案を作成するまで完了する` |
| キャンペーン設計 | `<父の日> 商戦向けに、対象商品<5>点・割引率・告知スケジュールをまとめた施策案を1枚にまとめるまで完了する` |
| 効果検証 | `先週実施した<クーポン施策>の前後で対象商品の売上を比較し、効果と次回改善案をレポートするまで完了する` |

## 定例化（/loop との組み合わせ）

毎日・毎週繰り返す集計系ゴールは `/loop` で自動反復にできる。

- 例：`/loop 1d <在庫の補充アラート ゴールコマンド>` → 毎日チェックしてLINE通知
- 例：毎週月曜の売上サマリを `/loop 7d ...` で定例化

定例化に向くのは「在庫補充アラート」「週次売上サマリ」「未対応問い合わせの優先順位付け」。
都度判断が要る「出品改善」「キャンペーン設計」は単発ゴール向き。

## 完了条件の語彙（送り先パターン）

完了判定を明確にするための定番の締めの言い回し：

- `…をLINEグループに送信するまで完了する`（通知＝完了。最も判定が明確）
- `…をMarkdownファイル <path> に保存するまで完了する`（成果物がファイル）
- `…の一覧を作成し本文に提示するまで完了する`（チャット上で提示）

迷ったら「LINEに送信するまで」を付ける。send_line_message の成功が即ち完了になり、
Stop hook の判定とも一致するため最も堅い。
